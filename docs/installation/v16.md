## Full MariaDB Performance Config

Paste the following into `99-erpnext-tuning.cnf`:

```ini
[mysqld]

# ── Character Set ─────────────────────────────────────────
character-set-client-handshake = FALSE
character-set-server           = utf8mb4
collation-server               = utf8mb4_unicode_ci

# ── InnoDB Buffer Pool ────────────────────────────────────
# Set to 50-70% of available RAM
innodb_buffer_pool_size        = 2G
innodb_buffer_pool_chunk_size  = 128M

# ── InnoDB I/O Performance ───────────────────────────────
innodb_file_per_table          = 1
innodb_flush_log_at_trx_commit = 2        # Slightly relaxed durability for speed
innodb_flush_method            = O_DIRECT # Bypass OS cache
innodb_log_file_size           = 512M
innodb_log_buffer_size         = 64M
innodb_io_capacity             = 400
innodb_io_capacity_max         = 800
innodb_read_io_threads         = 8
innodb_write_io_threads        = 8

# ── Connection Settings ───────────────────────────────────
max_connections                = 300
max_connect_errors             = 10000
wait_timeout                   = 300
interactive_timeout            = 300
connect_timeout                = 10

# ── Query Cache (disabled for MariaDB 10.6+) ─────────────
query_cache_type               = 0
query_cache_size               = 0

# ── Thread & Sort Buffers ────────────────────────────────
thread_cache_size              = 100
sort_buffer_size               = 4M
join_buffer_size               = 4M
read_buffer_size               = 2M
read_rnd_buffer_size           = 4M
tmp_table_size                 = 128M
max_heap_table_size            = 128M

# ── Slow Query Logging ───────────────────────────────────
slow_query_log                 = 1
slow_query_log_file            = /var/log/mysql/slow-queries.log
long_query_time                = 2
log_queries_not_using_indexes  = 0

# ── General & Binary Logging ─────────────────────────────
general_log                    = 0   # Keep OFF in production
skip-log-bin

# ── Table & Open File Limits ─────────────────────────────
table_open_cache               = 4000
table_definition_cache         = 2000
open_files_limit               = 65535

# ── Networking ──────────────────────────────────────────
bind-address                   = 127.0.0.1
max_allowed_packet             = 256M

[client]
default-character-set          = utf8mb4

[mysql]
default-character-set          = utf8mb4
```

## Setup database user
```
sudo mariadb
CREATE USER 'frappe'@'127.0.0.1' IDENTIFIED BY 'frappe';
GRANT ALL PRIVILEGES ON *.* TO 'frappe'@'127.0.0.1' WITH GRANT OPTION;
FLUSH PRIVILEGES;

CREATE USER 'root'@'127.0.0.1' IDENTIFIED BY 'frappe';
GRANT ALL PRIVILEGES ON *.* TO 'root'@'127.0.0.1' WITH GRANT OPTION;
FLUSH PRIVILEGES;
```

### Alter Host
```
ALTER USER 'frappe'@'127.0.0.1' IDENTIFIED BY 'frappe';
FLUSH PRIVILEGES;

ALTER USER 'root'@'127.0.0.1' IDENTIFIED BY 'frappe';
FLUSH PRIVILEGES;
```

### View Host
```
SELECT user, host FROM mysql.user WHERE user='frappe';
```

which bench

```

# Notes
- UV tool environments do not include pip by design.
- bench setup production relies on locating ansible via PATH; ensure the Bench tool bin directory is accessible.
- Avoid running general Bench commands with sudo; use sudo only for system administration tasks.
- If Supervisor reports no such group, verify that the generated supervisor.conf has been copied into /etc/supervisor/conf.d/ and reloaded.
- If you encounter permission errors after using sudo, restore ownership of your Bench directory with chown -R frappe:frappe.
- Keep ownership of the entire Bench directory with the frappe user.

## Restore Files
```
bench restore --with-public-files <public_tar_file_path>
bench restore --with-private-files <private_tar_file_path>
or 
tar -xvf files.tar -C /destination
or 
cp -r . /home/ubuntu/frappe-bench/sites/<site_name>/private/files/
or (best)
rsync -av private_files/ /home/ubuntu/frappe-bench/sites/<site_name>/private/files/
